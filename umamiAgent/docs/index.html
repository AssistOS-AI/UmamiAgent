Umami Agent Documentation

umamiAgent gives workspace users and agents controlled access to self-hosted traffic analytics. Callers retrieve website statistics or request a Markdown report without changing upstream Umami data. One Ploinky container runs the database, dashboard (with Umami's internal built-in MCP endpoint), and public AgentServer.

Analytics and report delivery

The original tools are umami_websites_list, umami_stats_get, umami_pageviews_get, umami_metrics_get, umami_events_list, umami_active_get, umami_sessions_get, and umami_report_generate. Sixteen more map one-to-one onto Umami's other read-only tools: umami_website_daterange, umami_event_stats, umami_event_series, umami_event_properties, umami_session_stats, umami_session_get, umami_annotations_list, umami_segments_list, umami_funnels_list, umami_funnel_run, umami_goals_get, umami_journey_run, umami_retention_run, umami_attribution_run, umami_revenue_get, and umami_performance_get. Tools accept the website identifier and applicable time range (epoch milliseconds) declared in mcp-config.json. The adapter validates input, calls Umami's built-in MCP endpoint over loopback with an internal API key, and redacts output.

A report gathers summary, pageviews, top pages, referrers, and countries. It writes Markdown under UMAMI_OUTPUT_DIR, defaulting to /shared/deliverables/umami, and returns filePath. The sanitized label determines the filename, so another report with the same label replaces that file. Read-only reporting prohibits upstream Umami changes while permitting local deliverables.

Dashboard and tool routing

Users with the explorer.access capability reach the dashboard through /base-agent-additional-server/umamiAgent/3000/. The image compiles that publication prefix, and startup checks build metadata before database initialization. The publication ingress restores the prefix and forwards to Next.js on loopback port 3001. It does not rewrite HTML or add a Router-root asset alias.

Browser tool calls (also limited to explorer.access) use /umamiAgent/mcp so the Router can supply per-tool authorization to AgentServer on port 7000. Umami's built-in MCP endpoint is internal: the ingress returns 404 for it on Router-forwarded requests. PostgreSQL data persists at /root/postgres. At start, a bootstrap step writes the internal API key, optionally enforces UMAMI_ADMIN_PASSWORD on the admin account, and seeds UMAMI_SEED_WEBSITES. Keep database passwords, app secrets, login passwords, and tokens out of logs and tracked files.

Website tracking

Umami Settings loads the existing website list when its modal opens. An operator selects a website and browser-reachable Umami URL, then copies the generated tracking snippet. The URL defaults to the public Router publication /base-agent-additional-server/umamiAgent/3000 on the Explorer's origin, whose script.js and api/send routes are the only public ones. Tracking events go directly to that Umami URL, not to the reporting MCP endpoint. Create websites in the Umami dashboard (or seed them with UMAMI_SEED_WEBSITES) and reopen settings to refresh the list. The plugin displays MCP failures.

Source and validation

tools/umami_tool.mjs owns tool validation and report files. scripts/start-umami-agent.sh supervises the embedded stack; scripts/umami-bootstrap.mjs enforces credentials and seeds websites; scripts/umami-ingress.mjs validates and relays the publication prefix and hides /mcp. The plugin lives in IDE-plugins/umami-settings/. DS001-coding-style governs source organization and tests.

Run npm test from umamiAgent/ for the settings, bootstrap, tool mapping, ingress, manifest, and supervisor checks under tests/. Native image and deployed Router validation remain separate. The Wiki is the canonical terminology source.
